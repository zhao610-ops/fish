# 定时自动发表

系统按设定时间循环执行：发现文章 → 全文检查 → 忠实翻译与核验 → 成稿审核 →
创建草稿 → 提交微信发表 → 查询结果并保存公开文章链接。

使用微信 `freepublish/submit` 和 `freepublish/get`
接口，不调用群发接口。账号必须具备对应接口权限，具体以该公众号的接口权限及真实接口返回为准。

请先完成
[全文翻译与发布配置](translation-publishing.md)。无合格文章时本轮跳过，旧组稿模式只允许预览。

## 首次启用

1. 配置 `trendpublish.config.ts` 中的模型、抓取服务、自有封面和公众号凭证，运行
   `deno task doctor`。
2. 在后台「文章方案」选择要执行的方案，设置来源、模板、配图与目标公众号，将「文章发表模式」设为「自动发表为公开文章」，保存。
3. 在「系统设置」选择同一方案，启用定时，选择每天执行时间与时区，关闭「仅预览」，保存定时规则。
4. 保持服务运行。保存后下一分钟读取新规则，无需重启。定时规则的预览开关优先于文章方案的默认预览开关。

配置文件中的发表模式示例：

```ts
features: {
  article: {
    dryRun: false,
    publisher: {
      provider: "weixin",
      accountId: "main",
      mode: "publish",
    },
    qualityGate: {
      enabled: true,
      forcePublish: false,
      allowForcePublish: false,
    },
  },
},
```

已初始化的文章方案与定时规则保存在数据库中，后续通过后台修改。修改配置文件不会覆盖已有方案和定时规则。

## 时间与循环

### 提前备稿与文章库

后台「运行」页顶部提供「待发文章库」，可点击「提前生成一篇（不发布）」进行抓取、翻译和完整审核。成功后入库，不连接微信、不占用真实发送记录；普通
dry-run 预览不会自动入库。

正式运行优先取当前账号、当前方案的待发库存，发送前再次检查全文安全。库存为空时普通运行继续现抓现译；指定「发表此篇」只处理指定库存，不会换另一篇发表。默认库存目标为
3 篇，成稿有效期 72 小时，可在部署配置 `features.article.translation` 中设置
`libraryTargetSize`（0～10）与 `libraryMaxAgeHours`（1～168）。

只有方案的定时已开启、定时不是仅预览、发表模式为 `publish`
时，系统才自动补库。每分钟检查，每小时每方案最多尝试补 3
篇，达到目标停止；失败有预算限制，不会无限重试。没有开启真实定时的方案不会在后台持续调用模型。

存稿位于 Docker 数据卷的
`article-library/`，重建镜像不丢失；状态显示待发、已过期、策略已变化、复查不通过、已占用或已发表。主题、排除范围、术语、质量阈值或有效期策略改变后旧库存不自动放行。发送超时的库存保持占用，需要核对微信结果，不能自动重发。

「正式发表此篇」需要页面再次确认，只发表一篇，不更改定时开关。API 也可通过
`POST /api/runs` 明确传入：

```json
{ "profileId": "article-default", "articleAction": "prepare", "dryRun": true }
```

先用 `GET /api/article-library?profileId=article-default`
获取库存编号与预览，再调用：

```json
{
  "profileId": "article-default",
  "articleAction": "publish-next",
  "libraryArticleId": "已获取的库存编号",
  "dryRun": false,
  "publishMode": "publish"
}
```

`publishMode`
只覆盖本次运行。调用必须携带后台认证令牌，不应把令牌写进链接或日志。

默认时区为 `Asia/Shanghai`，也可使用高级 Cron 设置：

| 规则           | 开始执行时间        |
| -------------- | ------------------- |
| `3 8 * * *`    | 每天 08:03          |
| `0 9,18 * * *` | 每天 09:00 和 18:00 |
| `0 */6 * * *`  | 每六小时一次        |
| `0 9 * * 1-5`  | 工作日 09:00        |

时间表示开始生成文章的时间，最终公开时间取决于抓取、模型生成和微信审核耗时。严格准点公开需要另外加入提前生成和待发表队列。

本地任务依次执行。同一方案尚在执行或排队时跳过它的新一轮，避免积压；单个任务失败不影响其他任务与下一轮。关闭定时后不再新增任务，已启动的任务会继续完成。

服务离线期间不会补发错过的时间点。重启后继续后续计划，恢复查询已提交且正在等待微信结果的文章；生成中断的任务不自动从中间步骤恢复。

## 查看结果

- `publishing`：已提交，等待微信发表结果。
- `succeeded`：任务完成；真实发表成功时，摘要和发表结果 JSON 中包含公开链接。
- `failed`：接口调用或微信审核失败，保留错误原因。查询暂时失败时留待下一轮重查。
- 质量审稿不通过：跳过本次发表，保留文章产物，后续计划继续。

提交超时或响应丢失时不自动重提，以免重复发表；此时需要核对微信后台发表记录。系统保留本次请求意图记录。

## 持续部署

Compose 从当前项目构建镜像：

```bash
sh scripts/docker.sh init
# 填写配置后执行
sh scripts/docker.sh up
sh scripts/docker.sh logs
```

详细步骤和备份方法见 [Docker 运行指南](docker.md)。后台默认地址为
`http://localhost:8000/dashboard/`，只监听本机。镜像内置后台页面并直接运行后端常驻服务。`restart: unless-stopped`
处理容器异常退出后的重启，服务器和 Docker 仍需持续运行。

本地开发使用
`deno task dev`，关闭终端或电脑休眠会中断调度。全文译刊真实发送目前只支持本地/Docker
的持久化存储；Cloudflare 存储缺少原子占位能力，因此会被门禁阻止。使用 Relay
时需同时更新 Relay，以支持发表状态查询。

本地运行记录改存 `runs/state.sqlite`，首次访问自动导入旧 `runs/state.json`
并保留旧文件。升级前停止旧版本进程，避免继续写入旧 JSON；备份整个数据目录。
